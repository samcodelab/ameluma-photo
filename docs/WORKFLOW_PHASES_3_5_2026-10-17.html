Visual review and workflow phases

17 October 2026 · Current implementation evidence · No commit or push

The review found and fixed real usability and targeting issues before adding recipes, universal Actions and creation/export integration. The existing processing and layer engines remain in use. Hosted screenshots and passing tests support the changes; they do not replace hands-on interaction, accessibility or physical-device testing.

Review gate — watermark, annotations and scope

  • Exposed the watermark design name beside Save Design. Existing layers remain the editable model; text, frame and tagline stay separate elements.
  • Kept 12 original templates and differentiated their proportions: compact signatures/copyright/social marks, a square serif monogram, a framed studio stamp, a vertical-accent modern layout and angled protection. Existing saved designs are not rewritten.
  • Empty watermark states explain authoring/import/application; zero-photo scopes do not offer a misleading Apply-to-0 action. Applying disables competing library actions while cancellation remains available.
  • Annotation selection now stays in Select when clicking empty canvas. Object labels identify actual kinds/text/callout numbers. Rectangle/ellipse/highlight/callout drawing has immediate outline feedback.
  • New arrows and lines follow gesture endpoints. A versioned direction flag preserves legacy rendering and saved output. Existing automatic callout renumbering and draft Undo/Redo remain shared.
  • Action-target tests deliberately leave unrelated gallery photos selected while editing one photo. Document, GIF and collage contexts never fall back to that gallery selection.

Validation: Core ToolboxTests/EditorDocumentTests and native WatermarkDesignUsabilityTests, EditorDocumentUsabilityTests, OutputUsabilityTests and SelectionAdapterTests. New captures show templates, designer and annotation canvas across platforms. Pointer/Pencil gesture quality is still a hands-on gate.

Phase 3 — visual reusable recipes

  • Added a versioned independent recipe record and native visual builder: Corrections → Resize → Filter → Watermark → Output. Enable steps and edit parameters; wider layouts keep preview beside controls, compact layouts put it above. Accessibility text starts with the preview collapsed.
  • Parameters start from recipe defaults, never implicitly captured from the current photo. Explicit watermark capture copies only watermark configuration. Photo crop, annotations, masks, retouch, colour traces, Auto Enhance and grain seeds stay on their original photos.
  • Recipe save owns immutable local image/design assets, writes atomically and rebinds owned assets after app-container relocation. Missing/invalid resources report errors.
  • Application freezes target identities/configurations, skips concurrent changes, reports changed/skipped/failed/not-run counts, supports stop/retry and groups successful edit changes into one Undo step. Reapplication refreshes only successful snapshots.
  • Conversion alone preserves dimensions; explicit resize overrides native sizing. Native sizing is now a sparse patch field and spatial changes revoke protective-coverage review as required.

Validation: RecipeTests verify semantic independence, geometry/patch round trips, unsupported versions, preview/export rendering equality and original hashes. ActionRecipeUsabilityTests cover failures, cancellation, concurrent edits, reapplication, Undo/Redo, resource ownership and relocation.

Phase 4 — universal contextual Actions / Command-K

  • Added a context-aware action system spanning current photo, explicit workspace selection, captured batch inputs, layered document, GIF, collage and unapplied draft.
  • Relevant actions expose existing tools and workflows. Scope is visible before execution; stale project/creation identities and busy states disable execution. Empty creations explain why export is unavailable.
  • Local commands such as “resize to 1920”, “convert to PNG” and “filter Warm” resolve real parameters through the existing engine. Search aliases cover common tool terminology. Explicit “selected images” requests cannot silently target the current photo.
  • Commands defer execution until their panel closes. Mac has Command-K and menu entry; mobile has visible Actions entries and a hardware keyboard shortcut registration.
  • Removed duplicate scope text from result rows and shortened helper text after large-text visual review. Keyboard arrow/Return/Escape handlers and accessibility scope labels are implemented.

Validation: ActionRecipeUsabilityTests exercise action filtering, parameter limits, scope, stale identities, disabled exports and watermark removal. Native captures include normal and accessibility-size parameter results. Actual hardware shortcut and VoiceOver activation remain unverified.

Phase 5 — creation and export integration

  • Mac Use Result transfers a finished layered document into Workspace or a new GIF using the existing document renderer, validated safe publisher and snapshot importer.
  • Finished sources receive a neutral full independent baseline, including in earlier Undo/Redo states, so old batch watermark/adjustments cannot leak into the flattened result. Existing workspace selection and batch input identities stay unchanged.
  • Universal creation Save/Export actions invoke the existing creation views. Privacy-review-required document layers block export/transfer until reviewed.
  • Recipe Export Changed Photos includes only successfully changed inputs and freezes their planned export requests. Later photo edits or selection changes cannot change those jobs. Sharing receives only successful outputs from the requested export.

Validation: ActionRecipeUsabilityTests render a real document, transfer it to Workspace/GIF, verify neutral output configuration through Undo/Redo and unchanged selection/batch IDs; frozen export tests verify later edits cannot alter queued snapshots. Existing output/collision/original-preservation Core tests remain green.

Assessment and remaining gates

The watermark templates now offer distinct signature, monogram, badge and protection forms, and the design name is discoverable. They are restrained editable starting points, not a claim that every typography/logo combination has had a professional brand review. The recipe builder is understandable without a programming model; its intentionally fixed order avoids promising operations the engine cannot perform. Action scope is explicit and stable. More physical-device and keyboard testing is needed before calling the experience release-ready.

  • Native UI automation was unavailable (native pipe startup failed). Evidence is source review, app-hosted SwiftUI captures, model/rendering tests and native Mac modifier-event tests. Full mouse, touch, Pencil, VoiceOver and hardware Command-K activation still need hands-on testing.
  • Large-text captures cover Recipes, Actions and mobile saved-watermark application. They do not establish every accessibility combination or keyboard-visible layout. Physical iPhone/iPad validation remains required.
  • Mac test-host logs contain repeated MDB_MAP_FULL messages. Their origin is unresolved; passing tests do not establish that they are harmless. Simulator logs also contain missing haptic-library and scroll-update warnings.
  • Recipes use the existing engine’s fixed canonical order. Arbitrary step reordering, automatic enhancement analysis as a recipe step, portable recipe exchange and automation-watcher migration are not part of this increment.
  • Recipe preview shows the first captured photo, debounces changes and uses the shared renderer. It is not an encoded compression comparison, and interactive latency or large-batch memory targets were not measured on an M1/8GB baseline.
  • Owned recipe watermark files are intentionally retained after recipe deletion: current photos, saved projects and history may still reference them. Dependency-aware garbage collection can be added later.
  • Multi-element watermark/document authoring remains Mac-first. Mobile supports saved-design import/application and the shared recipe/action workflows; it does not have full designer parity.
  • Finished document transfer is flattened to a new local PNG while the editable document remains intact. Workspace import is outside edit Undo; remove the finished source using normal workspace removal. Earlier history retains an independent baseline for that source.
  • Universal actions support deterministic local commands and aliases, not unrestricted natural-language interpretation. Unsupported operations are not fabricated.
  • The 24 filters are unchanged. Existing complex object-removal/retouch quality limitations remain. No claim of competitor performance parity or absence of all usability issues is made.
  • Public privacy/support URLs and distribution artifacts remain release blockers. Signing, bundle identifiers and storage identities were not changed. No commit or push was performed.
