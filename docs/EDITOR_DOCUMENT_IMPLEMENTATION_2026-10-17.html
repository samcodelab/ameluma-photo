Editable image documents: implementation stage

17 October 2026 · Mac authoring · shared FramepebbleCore · not committed or pushed

Implemented: the initial document/layer/text/shape/save/export foundation. This is a usable increment of the approved plan; it does not complete the entire general-purpose editor specification or its release acceptance gates.

Try it

  1. Use File → New Image Document, or select workspace photos and choose File → Open Selected Photos as Layers.
  2. Place an image, add editable text or a shape from the compact left toolbar. Select a layer to reveal its properties. Drag on the canvas, use resize/rotation handles, or expand Transform for numeric controls.
  3. Save an editable .ameluma document; Export creates a flattened image. Copy Flattened Image and Paste Image as Layer have explicit commands and preserve normal text clipboard actions.
  4. Return to Workspace without closing the document; use File → Open Documents to resume. Closing prompts to save or discard unsaved changes.

Implemented

  • Version-1 document model: image, editable text and shape layers; top-left pixel geometry
  • Portable package with owned immutable source resources, validated staged saves and atomic publication
  • Mac file type, native open/save coordination, session security bookmarks, dirty state and local crash recovery
  • Independent document history, grouped transforms/text interactions and active-target Undo/Redo
  • Native pointer layer movement, resize/rotation handles, numeric transforms, proportion constraint and flips
  • Visibility, locks, duplication, reordering, thumbnails, opacity and eight tested blend modes
  • SDR sRGB shared composition renderer, incremental layer materialization and bounded content cache
  • Fit/actual pixel view, zoom, scroll/pan and checkerboard; canvas boundaries independent of layers
  • Existing export/encoding validation and collision handling, flattened clipboard copy and image-as-layer paste/drop
  • Explicit captured workspace-photo inputs; preserve review-required state before document export

Architecture and compatibility

The new EditorDocument model is separate from existing workspace ProjectDocument schema 4 and sparse photo ConfigurationPatch overrides. Image layers capture effective ProcessingConfiguration records and copy required image resources, including image watermarks. Legacy processing order and internal module/storage identities remain unchanged. New document nodes use document-pixel geometry; old normalized photo recipes remain inside their legacy render boundary.

The shared composition renderer orchestrates the current ImageProcessor, semantic CoreText/CoreGraphics content and Core Image blend modes. It caches rendered content independently from layer placement with a 64 MiB/24-entry cap per renderer, and materializes the composed canvas incrementally rather than retaining a graph of every full-resolution source. Inactive document views clear their caches. Export uses immutable snapshots and the established publish/validate path. New composition output is SDR sRGB; source bytes remain unchanged.

Packages contain manifest.json and Resources/UUID.extension copies. Manifest and resource paths/counts/sizes are bounded, symlinks and path traversal are rejected, unsupported versions are blocked without rewriting files, and a staged complete package is validated before exclusive publication or atomic replacement. The Mac adapter coordinates saves and keeps a session security bookmark. Recovery packages and metadata preserve editable state and saved/dirty identity separately from workspace visibility.

Deleted layers are removed from the current document’s resource list; their local working copies remain available to session Undo. Duplicating a layer preserves any pending review requirement, even if the original layer is later deleted.

Known gates and limits

  • Real mouse/trackpad and VoiceOver interaction testing blocked by Cua native-pipe startup failure
  • Native hosted captures instantiate real views with programmatically populated state; they do not establish live usability
  • No measured end-to-end latency, peak-memory or M1 8 GB performance acceptance yet; no competitor performance claim
  • Current version limits: 200 layers/resources, 20,000 pixels per side and 50 MP canvas/layer bounds; limits do not guarantee all such documents fit physical-device memory
  • Old object-removal photographic quality gate remains open and its experimental UI remains gated
  • Mac test host continues logging MDB_MAP_FULL; origin not established; tests pass, diagnostic remains unresolved
  • Initial iPhone final run failed Simulator preflight; device was found shutdown, explicitly booted, and retry passed
  • Initial native capture failed on an unsupported /tmp write from the sandboxed host; keeping the screenshot in test attachments resolved it
  • Editable packages include originals and are not privacy-sanitized sharing artifacts; flattened export is separate
  • Session Undo is bounded to 80 semantic states; undo history itself is not restored across launches

Next foundation work is a shared document-region selection and sparse raster tile/history system, followed by selected-region edits and paint. General-purpose pixel tools should not be added as more photo-configuration arrays. Complete real input/accessibility/performance validation of this increment before calling it production-ready.
